# Aidoku 0.9 build 3 native decoder diagnostic

First actual macOS execution: https://github.com/LUC1DDREAM/my-aidoku-sources/actions/runs/34208333206 (success, Swift 6.1.2, macOS 15.7.9 arm64).

Both hosted production JSON URLs decoded all six sources. Community decoded 135. All package/icon relative paths resolved to experimental/sources and experimental/icons, and HEAD returned 200 (no image/package downloads). Six invalid controls rejected, omitted sourceUrl decoded nil, deep link URL roundtrip passed. HTML root failed the legacy array fallback. This does not reproduce iPhone networking/state.

`one-source.json` is generated by the successful Swift probe from our Asura entry with only required id/name/version plus absolute package/icon URLs. It is deliberately EXPERIMENTAL and does not replace the six-source production catalog. `six-source-control.json` retains all six entries and metadata; only list name and asset URL spelling differ (absolute URLs resolve to the same hosted artifacts). Hosting both on the same raw GitHub branch route permits a bounded per-entry/optional-metadata differential without breaking asset paths or borrowing Community IDs. The diagnostic is temporary and not a supported subscription.

Interpretation: if minimal fails too, six-source optional metadata is unlikely the differentiator; no claim of iOS proof. If minimal imports, the same-route six-source control distinguishes the optional-metadata/entry-set branch from the production-host route. Do not reset app data or remove Community.

Required modern layout: top-level object with name:String, sources:Array. Each source requires id:String, name:String, version:Int. Optional strings: iconURL, downloadURL, baseURL, minAppVersion, maxAppVersion, deprecated lang/file/icon. Optional string arrays: languages, altNames. Optional contentRating is integer enum 0/1/2; nsfw is Int. Optional sourceUrl is Foundation URL (normally omitted; overwritten with list URL by into(url:)). Optional list feedbackURL is String. Unknown keys do not fail synthesized decoding. No manifest, checksums, HTML or package fetch is required for list decode. Usable entries additionally need existing .aix and icon URLs; relative URLs resolve against the JSON document, NOT site root.
